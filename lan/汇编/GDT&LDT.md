### GDT 和 LDT

在保护模式下 所有的内存访问都需要经过 **全局描述符表(GDT)** 或 **局部描述符表(LDT)**.  这些**描述符表**中记录的都是 **段描述符**.

每个程序都有自己的 LDT, 但是一个系统只有一个 GDT



#### GDT (Global Descriptor Table)

在整个系统中, 全局描述符表只有一张(一个处理器对应一个GDT). GDT可以放在内存的任意位置, 但是CPU必须知道GDT在哪, 因此在系统启动的时候, GDT就会初始化了. 系统会用 指令`LGDT`  将 GDT的入口存入寄存器GDTR.  寄存器GDTR中存放了 GDT的基地址和表长界限.





#### 段描述符

一个 GDT段描述符占用8个字节, 包含三个部分:

- 段界限(20位), 占据 0~15位 和 48~51位, 前者存储低16位, 后者存储高4位

- 段基址(32位), 占据16~39位 和 56~63位 前者存储低24位, 后者存储高8位

- 段属性(12位), 占据40~47位 和 52~55位 段属性包括8种:

  - S属性

    - S = 0时, 该描述符对应的段是 系统段(system segment)
    - S = 1时,  该描述符对应的段是数据段（Data Segment）或者代码段（Code Segment）

    

  - TYPE属性, 存储段的类型信息, 属性的意义随S的不同而不同

    - 当S = 1时, 且段第40位即TYPE[0] = 0时, 标识该段为数据段, TYPE其他位的作为如下:

      | 位      | 作用         | 值为0时        | 值为1时              |
      | ------- | ------------ | -------------- | -------------------- |
      | TYPE[1] | 段的增长方向 | 向上增长       | 向下增长（例如栈段） |
      | TYPE[2] | 段的写权限   | 只读           | 可读可写             |
      | TYPE[3] | 段的访问标记 | 该段未被访问过 | 该段已被访问过       |

    - 当S = 1时, 且段第40位即TYPE[0] = 1时, 标识该段为代码段, TYPE其他位的作为如下:

      | 位      | 作用           | 值为0时        | 值为1时        |
      | ------- | -------------- | -------------- | -------------- |
      | TYPE[1] | 一致代码段标记 | 不是一致代码段 | 是一致代码段   |
      | TYPE[2] | 段的读权限     | 只能执行       | 可读、可执行   |
      | TYPE[3] | 段的访问标记   | 该段未被访问过 | 该段已被访问过 |

      一致代码段的“一致”意思是：当CPU执行jmp等指令将CS寄存器指向该代码段时，如果当前的特权级低于该代码段的特权级，那么当前的特权级会被延续下去（简单的说就是可以被低特权级的用户直接访问的代码），如果当前的特权级高于该代码段的特权级，那么会触发常规保护错误（可以理解为内核态下不允许直接执行用户态的代码）。
      如果不是一致代码段并且该代码段的特权级不等于（高于和低于都不行）当前的特权级，那么会引发常规保护错误。

    - 当 S = 0时, 表示该段是系统段

      | TYPE的值（16进制） | TYPE的值（二进制） | 解释                          |
      | ------------------ | ------------------ | ----------------------------- |
      | 0x1                | 0 0 0 1            | 可用286TSS                    |
      | 0x2                | 0 0 1 0            | 该段存储了局部描述符表（LDT） |
      | 0x3                | 0 0 1 1            | 忙的286TSS                    |
      | 0x4                | 0 1 0 0            | 286调用门                     |
      | 0x5                | 0 1 0 1            | 任务门                        |
      | 0x6                | 0 1 1 0            | 286中断门                     |
      | 0x7                | 0 1 1 1            | 286陷阱门                     |
      | 0x9                | 1 0 0 1            | 可用386TSS                    |
      | 0xB                | 1 0 1 1            | 忙的386TSS                    |
      | 0xC                | 1 1 0 0            | 386调用门                     |
      | 0xE                | 1 1 1 0            | 386中断门                     |
      | 0xF                | 1 1 1 1            | 386陷阱门                     |

  - DPL属性  表示访问该段需要的特权级, 范围是0~3, 越小特权级越高.

  - P属性  表示该段是否存在.  p=0时,该段在内存中不存在, p=1时该段在内存中存在.

  - AVL属性  intel保证该位不会被占用作为其他用途, 可以由应用程序自定义.

  - L属性   该属性仅在IA-32e模式下有意义，它标记了该段是否为64位代码段.  当 L = 1 时，表示该段是64位代码段.  如果设置了L属性为1，则必须保证D属性为0.

  - D/B属性(Default operation size / Default stack pointer size / Upper bound).. 

  - 该属性的意义随着段描述符是代码段（Code Segment）、向下扩展数据段（Expand-down Data Segment）还是栈段（Stack Segment）而有所不同。

    代码段（S属性为1，TYPE属性第三位为1）
    如果对应的是代码段，那么该位称之为D属性（D flag）。如果设置了该属性，那么会被视为32位代码段执行；如果没有设置，那么会被视为16位代码段执行。

    栈段（被SS寄存器指向的数据段）
    该情况下称之为B属性。如果设置了该属性，那么在执行堆栈访问指令（例如PUSH、POP指令）时采用32位堆栈指针寄存器（ESP寄存器），如果没有设置，那么采用16位堆栈指针寄存器（SP寄存器）。

    向下扩展的数据段
    该情况下称之为B属性。如果设置了该属性，段的上界为4GB，否则为64KB。

  - G属性  记录了段界限的粒度：

    G = 0 G=0G=0 时，段界限的粒度为字节
    G = 1 G=1G=1 时，段界限的粒度为4KB
    例如，当G = 0 G=0G=0 并且描述符中的段界限值为10000 1000010000，那么该段的界限为10000字节，如果G = 1 G=1G=1，那么该段的界限值为40000KB。

    所以说，当G = 0 G=0G=0 时，一个段的最大界限值为1MB（因为段界限只能用20位表示，2 20 = 1048576 2^{20}=10485762 
    20
     =1048576），最小为1字节（段的大小等于段界限值加1）。
    当G = 1 G=1G=1 时，最大界限值为4GB，最小为4KB。

    在访问段（除栈段）时，如果超出了段的界限，那么会触发常规保护错误（#GP）
    如果访问栈段超出了界限，那么会产生堆栈错误（#SS）
